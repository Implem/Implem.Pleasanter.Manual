# プリザンターユーザマニュアルの構造

編集すべき場所を特定できるように、プリザンターユーザマニュアル（以下PUM）全体の構造を理解しましょう。

## 日本語版と英語版は別プロジェクト

PUMは日本語版と英語版で**プロジェクトを分けて**います。

| ディレクトリ | 内容                                |
| :----------- | :---------------------------------- |
| `ja/`        | 日本語版（`mkdocs.yml` ＋ `docs/`） |
| `en/`        | 英語版（`mkdocs.yml` ＋ `docs/`）   |

両プロジェクトの`docs/`配下は、原則として同じディレクトリ構成になっています（翻訳作業の進み具合により、一部揃っていない場合があります）。編集したい言語のプロジェクトを選び、対応するパスのファイルを探してください。

## docs/配下はカテゴリごとのディレクトリで構成

`docs/`の直下は、以下のカテゴリディレクトリに分かれています（日本語版の例）。

| ディレクトリ        | 表示名       | 内容                                               |
| :------------------ | :----------- | :------------------------------------------------- |
| `getting-started/`  | はじめる     | プリザンターをはじめて使う人向けのセットアップ案内 |
| `update-info/`      | 更新情報     | バージョンアップなどの更新情報（ブログ形式）       |
| `products-info/`    | 製品情報     | 製品としてのプリザンターの紹介                     |
| `setup/`            | セットアップ | インストール・環境構築の手順                       |
| `ai-integration/`   | AI連携       | AIエージェント・MCPとの連携                        |
| `users-guide/`      | ユーザガイド | 画面操作を中心とした利用者向けの説明               |
| `managers-guide/`   | 管理者ガイド | サイト管理者・部署管理者向けの説明                 |
| `developers-guide/` | 開発者ガイド | API・スクリプトなど開発者向けの説明                |
| `FAQ/`              | FAQ          | よくある質問                                       |
| `info/`             | お知らせ     | その他のお知らせ                                   |

修正したい内容がどのカテゴリに当たるかを、この表から見当をつけてください。

## ディレクトリはさらにサブカテゴリへ分かれる

各カテゴリディレクトリの中は、内容に応じてさらにサブディレクトリへ分かれています。たとえば`users-guide/`（ユーザガイド）は、以下のように分かれています。

```
users-guide/
├── hands-on/         ハンズオン
├── custom-apps/      カスタムアプリ
├── folder/           フォルダ
├── site/             サイト
├── table/            テーブル機能
│   └── record-authoring/
│       └── create-records/   レコードの新規作成・インポート
├── access-control/   アクセス制御
├── smart-design/     スマートデザイン
├── wiki/             Wiki
├── dashboard/        ダッシュボード
├── announcement/     アナウンス機能
└── common/           共通機能
```

階層はカテゴリ→サブカテゴリ→（必要であれば）さらに細かい分類、という形で深くなっていきます。深さに決まった上限はなく、内容のまとまりに応じて必要なだけ分かれています。

## ナビゲーションの並びは.nav.ymlが決める

各ディレクトリには`.nav.yml`というファイルがあり、そのディレクトリの

-   左ナビゲーションでの**表示名**（`title`）
-   配下のページ・ディレクトリの**表示順序**（`nav`）

を決めています。

``` yaml
title: ユーザガイド

nav:
  - index.md
  - useful-function.md
  - hands-on
  - custom-apps
  - folder
```

> [!warning]
> ディレクトリ名のアルファベット順ではなく、`.nav.yml`の`nav`に書かれた順序で表示されます。ページやディレクトリを追加したときは、`.nav.yml`への追記を忘れないでください。追記を忘れると、そのページはナビゲーションに表示されません。

`.nav.yml`のYAML記法そのものについては、[YAMLマニュアル](yaml-howto.md)を参照してください。

## 各ディレクトリのindex.mdはカテゴリの入口

多くのディレクトリには`index.md`が置かれています。これはそのカテゴリのトップページで、多くの場合、配下のページへのカードリンク一覧を掲載しています。

``` md
---
title: アクセス制御
---

## 概要

本カテゴリは以下の内容を含みます。

<div class="grid cards" markdown>

-   [アクセス制御の概要](access-controls.md)
-   [レコードのアクセス制御（レコードの編集）](table-record-access-control.md)

</div>
```

新しくページを追加したときは、そのページが属するディレクトリの`index.md`にもカードリンクを追記してください。

## URLとディレクトリ構成の対応

`docs/`からの相対パスが、そのままページのURLになります（`.md`は末尾の`/`に変わります）。

| ファイル                                                                     | URL（例：日本語版）                                                              |
| :--------------------------------------------------------------------------- | :------------------------------------------------------------------------------- |
| `docs/users-guide/table/index.md`                                            | `/ja/manual/users-guide/table/`                                                  |
| `docs/users-guide/table/record-authoring/create-records/table-record-new.md` | `/ja/manual/users-guide/table/record-authoring/create-records/table-record-new/` |

編集すべきファイルが分からないときは、公開されているページのURLから、対応する`docs/`配下のパスを逆算すると見つけやすいです。

# 本文の記法

PUM は MkDocs のテーマ **mkdocs-materialx** で組んでいます。標準の Markdown に加えて、注意書き・折りたたみ・タブなどの記法が使えます。ここでは**よく使うものと、その使いどころ**をまとめます。

front matter（ファイル先頭のメタ情報）については[各ファイルの構造](file-structure.md)と[front matterリファレンス](markdown-howto.md)を、ナビゲーションの設定については[YAMLマニュアル](yaml-howto.md)を参照してください。

> [!note]
> ここに挙げた記法は**すでに日本語版で使われているもの**だけです。新しい記法を持ち込む前に、同じことが既存の記法でできないかを確かめてください。

## 注意書き（admonition）

```markdown
!!! warning "確認事項"
    インポートするCSVデータのタイトルと、プリザンターの項目名は一致させてください。
```

先頭が `!!!`、**中身は 4 つの空白で字下げ**します。見出しは省略できます。

| 種類 | 使いどころ |
| :--- | :--- |
| `note` | 補足。知らなくても操作は進む |
| `warning` | 読み飛ばすと操作が失敗する |
| `danger` | データが壊れる、元に戻せない |
| `tip` | 知っていると楽になる |

## 折りたたみ（collapsible）

`???` で始めると閉じた状態、`???+` で開いた状態になります。

```markdown
??? note "社員テーブル（クリックすると詳細が表示されます）"

    |レコードID|社員名|所属|
    |:--:|:--:|:--:|
    |1|山田|営業部|
```

**長いサンプルデータや、読み飛ばしてよい補足**に使います。本文の流れを切らずに済みます。

## 手順（steps）

番号付きの手順を、番号の丸と縦線で見せます。

```markdown
<div class="steps" markdown>

1.  「管理」→「テーブルの管理」→「エディタ」タブを選択します。
1.  項目を有効化します。

    ![エディタの設定画面](assets/xxxxxxxx.png)

</div>
```

- `<div>` の行に **`markdown`** を書き忘れると、中の Markdown が解釈されません
- **番号は全部 `1.` で構いません**（出力時に振り直されます）
- 番号付きリストが `<div>` の**直下**にないと、この見た目になりません

## タブ（content tabs）

同じ操作を環境ごとに分けて書くときに使います。

```markdown
=== "Windows"

    ```ps1
    dotnet Implem.CodeDefiner.dll _rds
    ```

=== "Linux"

    ```bash
    dotnet Implem.CodeDefiner.dll _rds
    ```
```

## キー（keys）

キーボードのキーは `++` で囲みます。

```markdown
++ctrl+shift+x++ を押します。
```

## 脚注（footnotes）

本文の流れを切りたくない補足に使います。

```markdown
期限付きテーブルでは「完了」項目に必ず値を入れてください。[^1]

[^1]: 記録テーブルの場合には「完了」項目はありません。
```

定義はページのどこに書いても、出力では一番下にまとまります。

## コードブロック

言語のあとに、表題・行番号・行の強調を指定できます。

````markdown
```json title="Rds.json" linenums="1" hl_lines="2 3"
{
  "SaConnectionString": "...",
  "OwnerConnectionString": "..."
}
```
````

| 指定 | 役割 |
| :--- | :--- |
| 言語（`json` `javascript` `bash` `ps1` など） | 色分け。**必ず付けてください** |
| `title="..."` | どのファイルの内容かを示す。**ファイル名だけ**を書く |
| `linenums="1"` | **行番号を出す。**値は開始番号 |
| `hl_lines="2 3"` | 行を強調する。範囲は `hl_lines="3-5"` |

> [!warning]
> **題名にパスを書かないでください。**`title="/web/pleasanter/Implem.Pleasanter/appsettings.json"` のような
> 区切りの空白が無い長い文字列は**折り返せず**、スマートフォン幅でページ全体が横にずれます（#279）。
> パスは地の文に書き、題名はファイル名だけにします。
>
> ```markdown
> 1.  /web/pleasanter/Implem.Pleasanter/を開いてください。
> 1.  appsettings.jsonに以下の設定を追加してください。
>
>     ``` json title="appsettings.json" linenums="1"
> ```

### 行番号

**本文から行を指し示したいときに付けます。**設定例やスクリプトは、行番号があると「3 行目の値を変えます」のように書けます。日本語版では、言語付きのコードブロック 695 のうち 191（約 3 割）が付けています。1 行だけのコマンドには不要です。

```` markdown
``` javascript linenums="1"
let myColumnName = 0;
```
````

長いコードを分けて載せるときは、**続きの番号から始められます。**

```` markdown
``` javascript linenums="14"
// 14 行目からの続き
```
````

行番号にはアンカーが付くため、`#__codelineno-0-3` のような形で**特定の行へリンクできます**。

### 行の強調

行番号と組み合わせると、長い設定例の中で「ここを直す」と示せます。

```` markdown
``` json title="Rds.json" linenums="1" hl_lines="2"
{
  "Dbms": "PostgreSQL",
  "TimeZone": "Tokyo Standard Time"
}
```
````

> [!note]
> コードの行に注釈を付ける機能（`content.code.annotate`）も有効ですが、**PUM ではまだ使っていません。**使い始める場合は、既存ページとの見え方の統一を先に決めてください。

## 表

両端にパイプを置き、区切り行で寄せを指定します。

```markdown
|パラメータ|型|必須|概要|
|:--|:--|:--:|:--|
|siteId|数値|○|対象のサイトID|
```

- 必須は **`○`**、必須でないものは **`-`** と書きます
- 概要の列は**体言止め**にします

## カード

カテゴリの入口ページ（`index.md`）で、配下のページを並べるのに使います。

```markdown
<div class="grid cards" markdown>

-   [レコードのインポート](table-record-import.md)
-   [レコードの新規作成](table-record-new.md)

</div>
```

> [!warning]
> **カードの表記は、左サイドナビの表記と一致させてください。**ナビは `.nav.yml`、カードは本文と、別々に書くため食い違いやすい箇所です（#249）。

## 画像

```markdown
![スケジュールの設定画面](assets/01-スケジュールの設定.png)
```

**代替テキスト（`![]` の中）は必ず書いてください。**「画面」「図」のような内容のない語ではなく、**その画像で何が見えるか**を書きます。画像ファイルの置き方は[画像を追加する](images.md)を参照してください。

## アイコン

```markdown
:material-arrow-right: 次へ進みます
:fontawesome-brands-windows: Windows
```

環境やOSを並べて示すときによく使います。名前は Material Design Icons と Font Awesome のものです。

> [!warning]
> **`:` で挟まれた語は、アイコンや絵文字に置き換わります。**
> 時刻の書式のように**半角コロンを含む文字列は、バッククォートでインラインコードにして守ってください**（#715）。
>
> `HH:mm:ss` の `:mm:` はミャンマー国旗の絵文字（🇲🇲）のショートコードです。
> そのまま書くと、本文では `HH🇲🇲ss` と表示されます。
>
> ```markdown
> NG: yyyy/MM/dd HH:mm:ss 形式で表示されます。
> OK: `yyyy/MM/dd HH:mm:ss` 形式で表示されます。
> ```
>
> 同じ表に書式の列があるときは、**その列はまとめてインラインコードにします。**
> 壊れているセルだけを直すと、表の中で見た目が揃いません。
>
> バックスラッシュで逃がす（`HH\:mm\:ss`）書き方でも表示は直りますが、
> **原稿が読みにくく、後から編集する人に消されやすい**ので使いません。

## ボタン

```markdown
[PDFを読む](https://example.com/foo.pdf){ .md-button }
```

リンクの直後に `{ .md-button }` を付けます。**そのページで最も進んでほしい行き先**に限って使ってください。並べると効果が薄れます。

## 強調

```markdown
==重要な語==
```

**太字（`**…**`）で足りることがほとんどです。**マーカーの強調は、本当に見落としてほしくない語だけに使ってください。

### 赤字にする

赤字にしたいところは、**クラスを付けた `<span>`** で書きます。**インラインの `style` は使いません。**

```markdown
<span class="pl-attention">※1</span>
<span class="pl-negative">**でない**</span>
<span class="pl-callout">➊</span> 項目一覧
```

| クラス | 使うところ |
|:--|:--|
| `.pl-attention` | 注意を引く赤字。「※」「※1」の記号や、注意の一文 |
| `.pl-negative` | 「でない」「含まない」「以外の」など、**読み飛ばすと意味が逆になる語**の強調 |
| `.pl-callout` | スクリーンショットに赤で描き込んだ**番号（➊➋❸）との対応づけ** |

**一文まるごとの注意は、赤字よりも「注意書き（admonition）」のほうが合います。**クラスの赤字は、**文の中の語や記号**に使ってください（#366）。

**太字や上付きにしたいときも、`style` ではなく Markdown で書きます。**

```markdown
<span class="pl-attention">**重要な注意**</span>
<span class="pl-attention">^※1^</span>
```

太字と一緒に使うだけなら、`<span>` の代わりに `**…**{ .pl-negative }` とも書けます。

**なぜ `style="color:red"` を使わないか。** 色がページごとに散らばると、直すときに全ページを触ることになります。また**純粋な赤（#ff0000）は白地でもダークモードでも読みにくく**（コントラスト比 約 4.0:1）、アクセシビリティの基準（AA、4.5:1）に届きません。クラスなら色の定義が `docs/stylesheets/extra.css` の 1 か所に集まり、ライトとダークで別の色を当てられます。

## チェックリスト

```markdown
- [x] 項目名とCSVのタイトルが一致しているか確認してください。
- [ ] まだ確認していない項目
```

「確認すること」を並べるときに使います。出力ではチェックボックスとして表示されます（クリックはできません）。

## 使わないもの

-   **本文中の任意改行**（段落の途中で改行しない）。画面幅で折り返し位置が変わるため、意図した位置では折り返されません
-   **生の HTML**。表の装飾や「強調」の節の `<span class="pl-…">` のように、Markdown の記法で書けないものを除き、Markdown で書いてください。旧CMS から持ち込まれた `style` 属性が残っているページがありますが、増やさないでください（#253）
-   **`style="color:red"` などの色の指定**。赤字にしたいときは「強調」の節のクラスを使ってください（#344）
-   **`<font color="red">` などの `<font>` 要素**。**HTML5 で廃止された要素**です。純粋な赤（#ff0000）はコントラスト比が約 4.0:1 で、アクセシビリティの基準（AA、4.5:1）に届きません。赤字にしたいときは「強調」の節のクラスを使ってください（#366）

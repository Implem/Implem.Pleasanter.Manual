# 文章の書き方

読み手が迷わず操作できることを最優先にします。ここに挙げるのは**社内で運用してきた規範**です。既存ページにはこれに沿っていないものもありますが、新しく書くとき・直すときはこちらに合わせてください。

記法については[本文の記法](markup-guide.md)を、用語の表記については[用語と表記](glossary.md)を参照してください。

## ページの型

内容によって、次のいずれかの見出し構成に沿わせます。**該当しない見出しは省きます。**空の見出しを置かないでください。

**機能の説明**

```
## 概要
## 注意事項
## 制限事項
## 前提条件
## 操作手順
## 対応バージョン
## 関連情報
```

**API・スクリプト・サーバスクリプトの説明**

```
## 概要
## 注意事項
## 制限事項
## 前提条件
## 構文
## パラメータ
## 戻り値
## 使用例
## 対応バージョン
## 関連情報
```

**FAQ**

```
## 回答
---
## 概要
## 注意事項
## 制限事項
## 前提条件
## 操作手順
## サンプルコード
## 対応バージョン
## 関連情報
```

## 各セクションの中身

| セクション | 書くこと |
| :--- | :--- |
| 回答（FAQ のみ） | 問いへの答えを **1 文**で。背景や手順は「概要」以降に回す |
| 概要 | ページ内容の要約。FAQ では回答の背景 |
| 注意事項 | **システムが停止する、データが壊れる**など、致命的なものだけ |
| 制限事項 | 仕様上の制約、他の設定に依存する事項 |
| 前提条件 | 権限の付与など、操作前に済ませておくこと |
| 操作手順 | 必要なら `###` で章立てし、画面の画像を添える |
| 対応バージョン | バージョンで挙動が変わるものを**表で**。ページ自体が機能追加で増えた場合は「機能追加」と書く |
| 関連情報 | 関係するページへのリンク |

## 文章の決まり

### ですます調で統一する

### 文中で改行しない

段落の途中で改行を入れないでください。画面幅によって折り返し位置が変わるため、意図した位置では折り返されません。

### 主語を意識して能動・受動を使い分ける

操作の説明（主語は利用者）は**能動**、結果の説明（主語はシステム）は**受動**で書きます。

- NG: インポートボタンがクリックされると、インポートダイアログを表示します。
- OK: インポートボタンをクリックすると、インポートダイアログが表示されます。

### 操作と結果を 1 文に詰め込まない

- NG: 一覧画面でレコードをクリックすると、編集画面が表示されます。
- OK:
  1. 一覧画面でレコードをクリックします。
  1. 編集画面が表示されます。

### 二重否定を使わない

- NG: 作成権限がないとレコードを新規登録できません。
- OK: レコードを新規登録するには「作成権限」が必要です。

### 特定の値は半角の丸括弧で囲む

## 題名の付け方

- 関連づけて書くときは「〇〇オブジェクト：☆☆メソッド」の形にし、**コロンは全角**にします
- FAQ の題名は、利用者が実際に問い合わせる**疑問形**にします（例:「テーブル名を変更したい」）
- 題名は**左サイドナビの表記と一致**させてください。別々の仕組みで決まるため食い違いやすい箇所です（#249）

## コードと設定例

- 引数・変数は**キャメルケース**（NG: `SiteId` / OK: `siteId`）
- 文字列は**シングルクォート**で囲む
- メソッドの 2 つ目以降の引数は、カンマの後に**半角空白**を入れる
- サンプルの変数・関数には **`my` / `My`** を付ける（例: `let myColumnName = 0`）
- パラメータ表では、必須を **`○`**、必須でないものを **`-`** と書き、概要の列は**体言止め**にする

サーバスクリプトのページには、次の注意書きを必ず入れてください。

> こちらはサーバスクリプト機能で使用するメソッドです。スクリプト機能では使用できません。

## 書き終えたら

- 見出しの構成が型に合っているか
- 手順と結果が分かれているか
- 段落の途中で改行していないか
- 題名・カード・左サイドナビの表記が一致しているか

を通しで見直してください。[受け入れの基準](review-and-ci.md)も確認しておくと、レビューの往復が減ります。

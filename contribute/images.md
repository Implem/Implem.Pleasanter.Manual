# 画像を追加する

**画像の実体は、このリポジトリに入っていません。**別のストレージに置き、配信時にそこから読み込んでいます。そのため画像の追加には専用の手順があります。

> [!warning]
> **画像を `ja/docs/**/assets/` などへ直接コミットしないでください。**
> git に入った画像は、PR を閉じても main にマージしても**履歴から消せません**。

## 置き場所と名前

追加したい画像は `_incoming/` に置きます。

```
_incoming/<ja または en>/<docs からのディレクトリ>/<好きな名前>.png
```

`ja/docs/FAQ/backup-restore/` のページに足すなら、次のようになります。

```
_incoming/ja/FAQ/backup-restore/01-スケジュールの設定.png
```

Markdown からは、いつもどおりの相対参照で書きます。**ファイル名はここに置いたままの名前**で書いてください。

```markdown
![スケジュールの設定画面](assets/01-スケジュールの設定.png)
```

## そのあと何が起きるか

PR を出すと、ワークフローが次を行います（#226）。

1. GUID を採番し、`<lang>/<ディレクトリ>/assets/<GUID>.png` としてストレージへ上げる
1. Markdown の参照を `assets/<GUID>.png` へ書き換える
1. `_incoming/` からファイルを消す
1. 以上をまとめたコミットを、PR のブランチへ自動で足す

プレビュー環境では、ストレージから配信された画像が表示されます。

手元で何が起きるかだけ見たいときは、次を実行してください（`--apply` を付けなければ変更しません）。

```bash
node scripts/incoming-images.mjs
```

## 気をつけること

- **どのページからも参照されていない画像は、取り込みで止まります。**先に Markdown を書いてください
- **既にある画像の差し替えも、新しい画像として足してください。**ストレージは全環境で共有、キャッシュは 1 年です。同じ名前を上書きすると本番へ即時反映され、読み込み済みの閲覧者には古い画像が最大 1 年残ります
- **代替テキストを必ず書いてください。**「画面」「図」ではなく、その画像で何が見えるかを書きます

## 手元では画像が表示されません

手元のビルドでは、画像はストレージを指さないため表示されません。ビルドのログに「画像が見つからない」という警告が大量に出ますが、**これは既知の状態**です。表示を確かめたい場合はプレビュー環境を使ってください。

## 公開リポジトリ（フォーク）から画像を提案するとき

上の自動化は、**フォークからのプルリクエストでは動きません。**ストレージへの資格情報をフォークに渡さない作りだからです（#282 で方針を決めました）。公開リポジトリから参加する方は、次の手順で画像を提案してください。

1. 画像は `_incoming/` に置かず、**issue かプルリクエストのコメントに添付**してください
1. どのページのどこに入れる画像か、**代替テキストの案**（その画像で何が見えるか）を書き添えてください
1. 本文の修正は、プルリクエストで送ってかまいません。画像を入れる位置には、仮に `<!-- 画像: 添付の 1 枚目 -->` のような目印を書いてください

> [!warning]
> **公開リポジトリへの添付は、その時点で誰でも見られます。**添付する前に、画面に個人名・メールアドレス・社内のサーバ名・顧客のデータなどが写り込んでいないかを確かめ、必要なら塗りつぶしてください。

添付していただいた画像は、弊社の担当者が次のように取り込みます。

1. 写り込み（個人情報・社外秘の情報）と、画面の言語がページと合っているか（英語版のページには英語の画面）を確かめる
1. `_incoming/` に置き、**社内のリポジトリのプルリクエスト**で取り込む（上の自動化が働く）
1. 取り込んだ先を、元の issue かプルリクエストに返信する

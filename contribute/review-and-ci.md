# 受け入れの基準

PR を出すと、自動の検査が走ります。**何を見られるかを先に知っておくと、往復が減ります。**

検査が走るのは、変更を原稿のリポジトリへ取り込んだあとです。公開リポジトリ側では走りません。

## 自動で見ているもの

### ビルドが通ること

日本語版・英語版の両方を MkDocs でビルドします。**片方でも失敗すると配信されません。**

### ナビゲーションから落ちるページがないこと

ビルドのログに次の警告が出たら、**直してから出してください。**

```
awesome-nav: The nav item '...' doesn't match any files or directories
```

`.nav.yml` が実在しないファイルを指しています。この状態のページは**左のメニューから辿り着けなくなります**（#229）。いまは 0 件なので、出たらその変更が原因です。

> [!note]
> 次の 3 つは**既知**です。直さなくて構いません。
>
> - 旧CMS由来のフルパスリンクが解決されないという INFO
> - 画像が見つからないという警告（画像はこのリポジトリに無いため）
> - `Plugin 'minify' option 'remove_comments': Unrecognised configuration name`

### 配信前の関門

## 人が見るもの

自動の検査では分からないところです。

- **題名・カード・左サイドナビの表記が一致しているか**（#249）。3 つは別々の仕組みで決まるため、食い違いやすい箇所です
- **[文章の書き方](writing-style.md)に沿っているか** — 見出しの構成、手順と結果の分離、能動・受動
- **[用語と表記](glossary.md)に沿っているか** — 製品名、画面の項目名
- **画面の画像と本文が食い違っていないか** — 本文の項目名を直すと、画像の中の文字と合わなくなることがあります
- **もう一方の言語をどうするか**（[日本語版と英語版](translations.md)）

## 落ちたときは

**閾値を下げて通すのではなく、原因を直してください。**この配信方式は毎回まるごと置き換えるため、壊れた成果物を配ると全面的に壊れます。

原因が分からないときは、PR にそのまま書いてください。落ちた検査の名前とログが手がかりになります。

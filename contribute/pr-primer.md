# はじめてのプルリクエストガイド

はじめてプルリクエスト（PR）を送る人向けに、必要な準備から送信までの手順をまとめました。事前に[コントリビュータガイド](index.md)の「法的留意事項」に目を通し、必要な同意書の提出を済ませておいてください。

## 1. 事前準備

| 項目 | 内容 |
| :--- | :--- |
| GitHubアカウント | まだ持っていない場合は作成してください |
| Visual Studio Code | 編集環境。[Visual Studio Codeのセットアップ](setup-vscode.md)を参照 |
| 書き方 | [文章の書き方](writing-style.md)・[本文の記法](markup-guide.md)を参照 |
| メタ情報・ナビゲーション | [front matterリファレンス](markdown-howto.md)・[YAMLマニュアル](yaml-howto.md)を参照 |
| PUMの構造 | [プリザンターユーザマニュアルの構造](pum-structure.md)・[各ファイルの構造](file-structure.md)を参照 |

## 2. リポジトリを手元に用意する

1. 公開リポジトリ「Implem.Pleasanter.Manual」を、ご自身のGitHubアカウントへフォークする
1. フォークしたリポジトリをクローンする

    ``` ps1
    git clone https://github.com/<あなたのアカウント>/Implem.Pleasanter.Manual.git
    cd Implem.Pleasanter.Manual
    code .
    ```

1. 作業用のブランチを作成する

    ``` ps1
    git switch -c <わかりやすいブランチ名>
    ```

## 3. 修正する

[プリザンターユーザマニュアルの構造](pum-structure.md)を参考に、修正すべきファイルを特定して編集してください。

- 誤字・説明の誤りの修正 … 該当ファイルを直接編集する
- ページの追加 … 新規ファイルを作成し、属するディレクトリの`.nav.yml`と`index.md`の両方に追記する（[各ファイルの構造](file-structure.md)を参照）

## 4. 手元で確認する

[README](../README.md)の手順で、Markdownとリンクが正しいかを確認してください。

``` bash
cd ja   # または en
mkdocs serve
```

> [!note]
> 画像はストレージ側から配信しているため、手元では表示されません。文章とリンクの確認に使ってください。

Visual Studio Codeの`markdownlint`拡張機能の警告にも目を通し、指摘があれば直してください。

## 5. コミットしてプッシュする

``` ps1
git add <編集したファイル>
git commit -m "<変更内容が分かるメッセージ>"
git push origin <ブランチ名>
```

## 6. プルリクエストを送る

1. GitHub上でフォーク元のリポジトリへアクセスする
1. 「Compare & pull request」からプルリクエストを作成する
1. 何を・なぜ直したかが伝わるように、変更内容を記載する
1. 日本語版・英語版の片方だけを直した場合は、「日本語版のみ」「英語版のみ」と書き添える（もう一方は弊社で追随します。[日本語版と英語版](translations.md)を参照）
1. 画像を足したい場合は、`_incoming/` に置かずにプルリクエストのコメントに添付する（[画像を追加する](images.md)を参照）

## プルリクエストを送ったあと

> [!warning]
> 公開リポジトリは配信元ではなく、このリポジトリ（社内）の内容を定期的に写したスナップショットです。そのため、**いただいたプルリクエストは公開リポジトリ上ではマージされません。**

内容を弊社の担当者が確認し、問題がなければ社内リポジトリへ取り込みます。取り込み後、次回の同期で公開リポジトリへ反映され、取り込み先が分かる形でプルリクエストにお返事したうえでクローズします。

> [!note]
> クローズされても、内容が採用されなかったという意味ではありません。

軽微な誤字・誤りの指摘だけであれば、プルリクエストを作らず[ISSUEを掲出する](issue-primer.md)方法でも構いません。
